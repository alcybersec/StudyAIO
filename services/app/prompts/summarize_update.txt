## Output Requirements

Produce an UPDATED markdown summary that merges the existing summary with the new content. Keep EXACTLY these sections in this order:

1. `# {{ course_code }} — Week {{ week }}: <Topic>` (keep or refine the topic)

2. `## Overview` — Update the contextual overview to incorporate new material. If the existing summary lacks an Overview, create one.

3. `## Key Concepts` — Merge and expand the hierarchical subsections (### and #### headers). For new concepts:
   - Explain the "what", "why", and "how" in paragraph form
   - Weave in real-world examples and case studies from the new content
   - Use tables where comparison or structured data is natural
   - Place new concepts in logical order relative to existing ones
   - CITE EVERY LINE: every paragraph, lead-in sentence, bullet, numbered step, table row, formula line and code line ends with the source marker(s) it comes from, e.g. `[p.3]`. In a table the marker goes inside the last cell of each row; for a fenced formula or code block, the line introducing it ends with the marker. Cite only markers that appear in the content above or already in the existing summary; never invent a page. A claim you cannot cite does not belong, and a line without a marker is a defect.
   - Write every formula in plain text exactly as the lecture writes it, in inline code or a code block. Do NOT use LaTeX (`$...$`, `\text{}`, `\bmod`): it does not render for the student and it re-spells the lecture's symbols.
   - Convert any flat bullet-point lists from the existing summary into proper subsection explanations
   Do NOT produce a flat bullet-point dump. Think like a tutor explaining the material.

4. `## Definitions` — Merge definition tables, add new terms, remove exact duplicates.

5. `## Diagrams & Visual Descriptions` — Merge diagrams. For important new processes or architectures, create ASCII art diagrams with explanatory text. Keep ONLY images that aid understanding (architecture diagrams, flowcharts, process diagrams, data models). REMOVE simple shapes, clip art, stock photos, decorative images, and screenshots of text/tables. If no valuable visual content remains, write "No diagrams in this lecture."

6. `## Code Examples` — Merge code examples. Ensure all code has inline comments explaining significant lines. If none, write "No code examples in this lecture."

7. `## Formulas & Algorithms` — Merge the exact, complete quantitative content, in plain text inside code blocks, each item followed by its source marker: every formula with all its cases and conditions, every base case, every complexity and named property, and every worked example with its given inputs, intermediate values and final result (the lecture's actual numbers, never a generic description). Keep what the existing summary had; add what the new content has. Write "No formulas in this lecture." only if neither contains any.

8. `## Key Takeaways` — Merge and update the distilled insights. Write as "so what?" statements, not just restated facts. If the existing summary has "Potential Exam Topics" instead, convert it to Key Takeaways style.

9. `## Connections` — Update the links to other lectures using ONLY what the lecture content and the existing summary contain. Keep connections the lecture itself states; add new ones the new content states, attributed to the lecture. Name another week only if the lecture names it, by title or topic, and NEVER state or imply what another week taught. Remove any industry, market, career or real-world-adoption paragraph the lecture did not discuss, and any named technology, standard or sector it did not mention. If nothing remains, write one plain sentence: "This lecture does not link to other material, and no other weeks were available to compare against."

10. Footer — REQUIRED, never omitted. The last thing in the summary, after the final line of `## Connections`, is a line containing only `---`, then, on the very next line, `*Sources: <list source artifacts>. Version: <increment>.*`. It is not part of the Connections text: a summary that ends at `## Connections`, or whose Sources line has no `---` line above it, is rejected. Emit the metadata block after it.

## Rules
- Merge, do not replace — preserve information from the existing summary
- Add new content from the new lecture material
- Remove exact duplicates but keep complementary information
- If the existing summary uses the old format (flat bullet Key Concepts, Potential Exam Topics, Summary section), restructure it into the new format during the merge
- Increment the version number in the footer
- Preserve technical accuracy
- Completeness checklist, mandatory. Before you write, list every formula, recurrence (each case), base case, condition, complexity, property, worked example (with numbers and result) in BOTH the existing summary and the new content. After you write, tick each off against the updated summary; anything unticked goes in before you finish.
- If the lecture doesn't say it, don't write it: add no fact, caveat, variant or improvement that neither the new content nor the existing summary contains, even when it is true. Do not drop a fact the lecture states.
- Write as a tutor teaching the material, not listing facts
- Prefer paragraph-form explanations over flat bullet lists for conceptual material
